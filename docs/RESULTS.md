# 真实数据实验结果（v4：41 维 + 硬负样本 + 信誉层）

> 记录用公开真实数据集跑出的全部结果，可直接作为论文第四章的数据来源。
> 生成时间：2026-10-31

---

## 1. 数据来源与构建

| 项目 | 数值 |
|---|---|
| 上游数据集 | ISCX-URL-2016 派生公开集（`url,label`，good/bad） |
| 原始行数 | 420 464 |
| 去脏行 → 只留带真实路径 → 去重 | 361 067（正常 300 205 / 恶意 60 862） |
| 抽样 | 52 000（正常 40 000 / 恶意 12 000），24 451 个域名 |
| **硬负样本（新增）** | **1 048 条，354 个域名** |
| **实验总量** | **53 048 条** |

### 硬负样本是什么

原始数据的正常样本多是通用网页，**银行、政务、邮箱的登录页几乎没被覆盖**：正常样本中路径含 login 类词的仅 357 条（0.89%），而恶意样本中这一比例是 9.68%——相差 10.9 倍。模型因此把"登录词"学成了强信号，导致 `icbc.com.cn/login` 这类真实登录页被误判。

硬负样本的做法：挑选各行业真实存在的登录入口域名（国内银行、支付、邮箱、政务、高校、国外主流站点），按常见路径拼出 URL，标为正常。

- 覆盖 354 个域名，1 048 条 URL
- 属于"真实域名 + 常见路径"的半合成数据，作用是让模型见到"干净域名 + login 路径"的组合
- 生成脚本：`scripts/build_hard_negatives.py`，可复现

## 2. 特征体系：26 维 → 41 维

原 26 维全是"整体计数"，分不清"主机名里的 login"和"路径里的 login"。新增 15 维把统计口径拆到主机名与路径两个层面。

（详见 v1 报告，此处略）

### 本轮修复的两个特征 bug

| Bug | 现象 | 修复 |
|---|---|---|
| 二级后缀解析错误 | `icbc.com.cn` 的可注册域被算成 `com.cn`，导致品牌词误判 | 引入 25 个常见二级后缀（com.cn / co.uk / com.au …），正确切分 |
| 品牌词裸子串匹配 | `ebank.cmbchina.com` 里的 `ebank` 命中品牌词 `bank` | 改为词边界匹配，要求前后不是字母数字 |

影响面：972 条（1.87%）+ 41 条（0.08%）。

## 3. 消融实验与切分对照

| 组 | 数据 | 特征 | 准确率 | F1 |
|---|---|---|---|---|
| A | 52 000 条 | 有 bug | 92.60% | 0.8330 |
| B | 52 000 条 | **修复后** | **92.70%** | **0.8340** |
| C | **+ 硬负样本**（53 048 条） | 修复后 | 91.91% | 0.8235 |

**结论：修 bug 让指标微涨（+0.001），硬负样本让 F1 下降约 0.01。**

这是有意的取舍：**用 1 个点的整体 F1，换掉银行、政务、邮箱登录页的系统性误报**。在真实部署里，把 `icbc.com.cn` 判成恶意对用户信任的伤害，远大于多漏一个钓鱼站。

> 注：C 组的测试集与 A/B 不同（分组切分随数据变化），三组数字不能严格逐项比较，只看趋势。

### 切分方式对照（同一模型、同一数据）

| 切分方式 | 准确率 | 精确率 | 召回率 | F1 | AUC | 域名重叠率 |
|---|---|---|---|---|---|---|
| 随机切分 | 93.32% | 88.17% | 81.37% | 0.8464 | 0.9747 | **60.5%** |
| 分组切分 | 90.62% | 79.92% | 80.21% | 0.8007 | 0.9494 | 0% |

随机切分把 F1 高估 0.046、准确率高估 2.70 个百分点。测试集里 60.5% 的样本，其域名在训练集出现过——这就是"背答案"。

> 早期用合成数据做同样对照时，分组切分反而略高（+0.46 个百分点），因为合成数据里恶意域名之间没有共享结构。换成真实数据后规律立刻显现——**评估方法本身也要在真实数据上验证**。

## 4. 最终效果

| 指标 | 起点（26 维 + RF） | 最终（41 维 + 硬负样本 + XGBoost） |
|---|---|---|
| 准确率 | 86.63% | **91.91%** |
| 精确率 | 66.16% | **84.42%** |
| 召回率 | 85.31% | 80.38% |
| F1 | 0.7453 | **0.8235** |
| AUC | 0.9343 | **0.9625** |
| 误报数 | 1 054 | **360** |
| 模型体积 | 7.4 MB | **0.9 MB** |
| 单条延迟 | 5.6 ms | **0.26 ms** |

精确率从 66% 提到 84%，告警可信度从"三条错一条"变成"六条错一条"。

## 5. 模型对比（分组切分，53 048 条）

| 模型 | 准确率 | 精确率 | 召回率 | F1 | AUC | 训练 | 单条推理 |
|---|---|---|---|---|---|---|---|
| **XGBoost ★** | 91.91% | 84.42% | 80.38% | 0.8235 | **0.9625** | 1.9 s | **0.26 ms** |
| 梯度提升树 | **91.98%** | **84.85%** | 80.13% | **0.8243** | 0.9611 | 3.5 s | 1.72 ms |
| 随机森林 | 90.62% | 79.92% | 80.21% | 0.8007 | 0.9494 | 18.5 s | 11.4 ms |
| 决策树 | 87.88% | 76.18% | 70.40% | 0.7318 | 0.8860 | 0.4 s | 0.15 ms |
| 逻辑回归 | 78.31% | 52.60% | 77.08% | 0.6253 | 0.8759 | 0.6 s | 0.37 ms |

### 选型规则的三次迭代（答辩可讲）

1. **第一版**："差距小于 0.5 个百分点时优先选随机森林，理由是特征重要性可解释。"
2. **第二版**：实测推翻——随机森林模型 162 MB、单条 22 ms，XGBoost 只有 0.9 MB、0.41 ms 且 F1 更高，XGBoost 同样能输出特征重要性。
3. **第三版（现行）**：**先按 F1 排序，再在"与第一名差距小于 0.002"的候选里取推理最快的**。理由：0.002 以内的 F1 差异没有统计意义，但延迟可能差一个数量级。

本轮即由该规则选出 XGBoost：F1 只比梯度提升树低 0.0008，推理快 6.6 倍。

## 6. 信誉层（域名白名单）

新增 `src/malurl/reputation.py`：对已知可信域名直接放行，**模型不参与计算**。

- 覆盖 66 个域名：国内银行/支付、邮箱门户、政务、高校、国外主流站点
- 匹配规则"后缀 + 点"：`www.icbc.com.cn` 命中，`icbc.com.cn.evil.tk` 不命中
- 命中时接口返回 `source="whitelist"`、`score=0`、`label=benign`，并计入 `malurl_whitelist_total` 指标

**为什么需要它**：模型负责"没见过"的域名，白名单负责"已知可信"的域名。工商银行登录页误判一次对用户信任的伤害，远大于多抓一个钓鱼站。这是纵深防御的标准分层。

**安全性**：白名单不放宽仿冒判定，实测——

| URL | 结果 | 来源 |
|---|---|---|
| `https://www.icbc.com.cn/login` | benign 0% | whitelist |
| `http://icbc.com.cn.evil.tk/login` | **malicious 99.96%** | model |
| `http://icbc-secure.tk/login` | **malicious 99.99%** | model |

## 7. 银行登录页问题：从误判到修复

| URL | 修复前 | 修复后 |
|---|---|---|
| `www.icbc.com.cn/login` | 77.28% 恶意 | **0.05% 正常** |
| `ebank.cmbchina.com/login` | 97.29% 恶意 | **0.08% 正常** |
| `www.ccb.com/login` | — | 0.03% 正常 |
| `12306.cn/account/login` | — | 0.74% 正常 |
| `accounts.google.com/signin` | — | 0.12% 正常 |
| `icbc-secure.tk/login`（仿冒） | 99.95% 恶意 | **99.95% 恶意** ✅ |

**真实银行放行、仿冒银行依然拦截**——这是本轮最重要的验证。

### 归因（XGBoost 贡献分解）

修复前 `icbc.com.cn/login` 的推高项：诱导词个数 +1.645、顶级域长度 +1.432、最长路径段 +0.575。而同一域名的首页只有 47.78%——**是 `/login` 这个路径把它推过线的**。

## 8. 剩余误报

阈值 0.5 时，误报主要来自短路径 + 随机 ID 的站点：

```
http://sell.com/25GWXR
http://sell.com/24WTLW
http://twitcam.livestream.com/7cjlo
```

这类"短链式 ID 路径"与恶意站点的随机路径在结构特征上几乎无法区分，属 URL 特征本身的边界。

改进方向：
1. 负样本继续补充带随机 ID 的正常站点
2. 引入域名注册年龄、证书信息（信誉维度）
3. 对路径做语义分词，区分"业务 ID"与"随机串"
